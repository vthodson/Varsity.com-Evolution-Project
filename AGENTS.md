# Varsity.com Evolution

## Purpose

This repository is the working project for the evolution of Varsity.com.

The project includes product strategy, experience strategy, information architecture, content strategy, technical exploration, prototypes/wireframes, and implementation work related to the future Varsity.com experience.

This project originated in a ChatGPT Project called **Varsity.com Evolution**. A significant amount of product and UX thinking happened there before Codex was connected to this repository. The files in this repository capture much of that work and should be treated as important project context.

## Source of Truth

Before making recommendations or changes:

1. Inspect the existing repository.
2. Read the relevant project documentation.
3. Understand what has already been decided or explored.
4. Build on existing work rather than starting over.

Do not assume the current production Varsity.com website represents the desired future state.

When repository documentation conflicts with assumptions, prefer the repository documentation.

When documents conflict with each other, identify the conflict rather than silently choosing one.

## Product Context

Varsity.com serves multiple audiences and business needs, including athletes, coaches, parents/families, programs/teams, and Varsity business stakeholders.

The evolution of Varsity.com is broader than a visual redesign. Work may involve:

- Product and experience strategy
- Information architecture and navigation
- Content strategy
- Marketing and SEO experiences
- Competition and event discovery
- Camps and other Varsity experiences
- Personalized or audience-aware experiences
- Reusable digital components
- Multi-brand/design-system considerations
- Performance and accessibility
- CMS/content-management needs
- Integration with other Varsity platforms and services
- Technical architecture and implementation

Use the repository's current documentation to determine the latest requirements and direction for each area.

## How to Work on This Project

When asked to work on Varsity.com:

- Inspect relevant existing files before creating something new.
- Preserve and extend work that already exists.
- Clearly distinguish between documented decisions, proposals, and your own recommendations.
- Do not replace established product decisions without explaining why.
- Favor reusable, scalable solutions over one-off implementations.
- Consider the complete customer experience, not just individual pages.
- Consider mobile and desktop experiences.
- Consider accessibility, performance, SEO, analytics, content management, and maintainability where relevant.
- Keep product/business intent connected to technical implementation.
- Prefer simple explanations when communicating technical concepts to non-engineering stakeholders.

## Git Safety

This repository is connected to the existing GitHub project and contains active Varsity.com Evolution work.

Unless explicitly asked:

- Do not delete existing project files.
- Do not overwrite significant existing work.
- Do not force-push.
- Do not rewrite Git history.
- Do not merge branches.
- Do not make destructive changes.

Before substantial changes, explain what you intend to change.

## Keeping Context Current

The repository should increasingly become the durable source of truth for the project.

When important new decisions are made during Codex work, update the appropriate project documentation rather than relying only on chat history.

If a new decision materially changes the project's direction, ensure the relevant strategy, architecture, planning, or README documentation reflects that change.

Keep `AGENTS.md` focused on durable project-level guidance. Put detailed requirements and evolving decisions in the appropriate project documents instead of allowing this file to become a duplicate project plan.
